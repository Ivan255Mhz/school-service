# AGENTS.md

## Режим работы

При выполнении задач **не действовать ваншотом**. Всегда:

1. **Анализ** — сначала изучить проблему: прочитать файлы, найти связи, понять причину
2. **Декомпозиция** — разбить задачу на подзадачи
3. **Выполнение** — реализовать пошагово с проверкой промежуточных результатов
4. **Валидация** — проверить build, протестировать, убедиться что ничего не сломалось

## Использование субагентов

Для сложных задач **использовать субагентов** через инструмент `task`:

- **explore** — для быстрого поиска файлов, анализа кода, чтения нескольких файлов параллельно
- **general** — для выполнения нескольких единиц работы параллельно

### Когда использовать субагентов

- Нужно прочитать и проанализировать 3+ файла одновременно
- Нужно найти все места использования переменной/класса/метода
- Нужно сделать одинаковые изменения в нескольких файлах
- Нужно исследовать незнакомую часть кодовой базы

### Когда НЕ использовать субагентов

- Одна простая правка в одном файле
- Запрос сборки или деплоя
- Коммит и push

## Порядок действий при исправлении бага

1. Найти файлы, связанные с проблемой
2. Прочитать их (параллельно через explore-агента если нужно)
3. Определить корневую причину
4. Спланировать изменения
5. Внести изменения
6. `npm run build` — проверить сборку
7. Исправить ошибки компиляции если есть
8. `vercel --yes --prod` — задеплоить
9. `git add -A && git commit && git push` — закоммитить
