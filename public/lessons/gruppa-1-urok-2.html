1. Наследование

Наследование позволяет создать новый класс на основе уже существующего, переиспользуя его поля и методы и добавляя (или переопределяя) своё поведение. Класс, от которого наследуют, называется базовым (родительским), а класс, который наследует — производным (дочерним).

public class Vehicle {
    public string Name { get; set; }
    protected int Speed { get; set; }

    public Vehicle(string name, int speed) {
        Name = name;
        Speed = speed;
    }

    public void Describe() {
        Console.WriteLine($"{Name}, скорость: {Speed} км/ч");
    }
}

// : Vehicle означает "Tank наследует от Vehicle"
public class Tank : Vehicle {
    public int Armor { get; set; }

    // base(...) вызывает конструктор родителя
    public Tank(string name, int speed, int armor)
        : base(name, speed) {
        Armor = armor;
    }
}

Tank t = new Tank("Т-34", 45, 75);
t.Describe(); // метод унаследован от Vehicle

protected — доступ для наследников

private члены класса недоступны даже дочерним классам. Модификатор protected открывает доступ полю или методу только внутри самого класса и его наследников — снаружи оно по-прежнему скрыто.

МодификаторДоступ внутри классаДоступ в наследникахДоступ снаружи
public✓✓✓
protected✓✓✗
private✓✗✗

sealed — запрет дальнейшего наследования

Если класс помечен как sealed, от него больше нельзя унаследоваться. Это полезно, когда вы хотите зафиксировать поведение класса и защититься от неожиданных переопределений.

public sealed class SuperWeapon : Vehicle {
    // от SuperWeapon унаследоваться больше нельзя
}

3. Полиморфизм

Полиморфизм («много форм») — это способность объектов разных производных классов по-разному реагировать на один и тот же вызов метода. В C# это реализуется через пару ключевых слов: virtual в базовом классе и override в производном.

public class Vehicle {
    public string Name { get; set; }

    // virtual разрешает наследникам переопределить этот метод
    public virtual void Move() {
        Console.WriteLine($"{Name} едет вперёд.");
    }
}

public class Plane : Vehicle {
    // override заменяет поведение родителя
    public override void Move() {
        Console.WriteLine($"{Name} взлетает в небо!");
    }
}

Главная магия: массив базового типа

Самое интересное происходит, когда мы храним разные объекты в списке базового типа — вызывается тот метод, который реально переопределён в конкретном объекте, а не в объявленном типе переменной. Это и называется динамическое связывание (runtime polymorphism).

List<Vehicle> fleet = new List<Vehicle> {
    new Tank("Т-34"),
    new Plane("Ил-2"),
    new Boat("Торпедный катер")
};

foreach (var v in fleet) {
    v.Move(); // у каждого своя реализация Move()!
}
// Т-34 едет вперёд.
// Ил-2 взлетает в небо!
// Торпедный катер рассекает волны.

override vs new (сокрытие метода)

Если вместо override написать new, метод не переопределяется, а скрывается — при вызове через переменную базового типа выполнится версия родителя, а не наследника. Это частая ошибка новичков, поэтому почти всегда нужен именно override.

5. Абстрактные классы

Иногда базовый класс существует только для того, чтобы задать общую структуру, но сам по себе не должен создаваться как объект — например, странно создавать «просто юнита» без конкретного типа. Для этого используется abstract.

public abstract class Unit {
    public string Name { get; set; }

    // abstract-метод не имеет тела — его ОБЯЗАН реализовать каждый наследник
    public abstract void Attack();

    // обычный метод можно оставить с готовой реализацией
    public void Introduce() {
        Console.WriteLine($"Юнит: {Name}");
    }
}

// var u = new Unit(); — ОШИБКА КОМПИЛЯЦИИ, нельзя создать абстрактный класс

// а вот наследник обязан реализовать Attack():
public class Warrior : Unit {
    public override void Attack() {
        Console.WriteLine($"{Name} рубит мечом!");
    }
}

Абстрактный класс — это компромисс: часть поведения уже реализована и наследуется как есть (Introduce()), а часть обязательно нужно дописать в каждом наследнике (Attack()).

6. Интерфейсы

Интерфейс — это «чистый контракт»: он описывает что класс должен уметь делать, но не содержит собственной реализации и полей с данными. Класс может реализовать сразу несколько интерфейсов, хотя унаследоваться может только от одного класса.

public interface IDamageable {
    void TakeDamage(int amount);
}

public interface IMovable {
    void Move(int distance);
}

// класс может реализовать сразу оба интерфейса через запятую
public class Tank : Vehicle, IDamageable, IMovable {
    public int Armor { get; set; }

    public void TakeDamage(int amount) {
        Armor -= amount;
    }

    public void Move(int distance) {
        Console.WriteLine($"Танк проехал {distance} метров");
    }
}

Интерфейс vs абстрактный класс

Абстрактный классИнтерфейс
Множественная реализацияНет, только один базовый классДа, сколько угодно интерфейсов
Поля с даннымиМожет иметь поля и конструкторНе может иметь поля состояния
Готовая реализация методовМожет содержать обычные методыОбычно только сигнатуры (контракт)
Когда использоватьКогда классы объединяет общая природа и общий кодКогда нужно описать способность («умеет летать», «умеет атаковать») независимо от иерархии

8. Практические задания

Задание 1: Простое наследование

Создайте базовый класс Animal со свойством Name и методом MakeSound(), который выводит «...издаёт звук». Унаследуйте от него класс Dog.

public class Animal {
    public string Name { get; set; }
    public Animal(string name) { Name = name; }
    public void MakeSound() {
        Console.WriteLine($"{Name} издаёт звук.");
    }
}

public class Dog : Animal {
    public Dog(string name) : base(name) { }
}

Задание 2: Переопределение поведения

Сделайте MakeSound() из предыдущего задания virtual, а в Dog переопределите его так, чтобы выводилось «...лает: Гав!».

public class Animal {
    public string Name { get; set; }
    public Animal(string name) { Name = name; }
    public virtual void MakeSound() {
        Console.WriteLine($"{Name} издаёт звук.");
    }
}

public class Dog : Animal {
    public Dog(string name) : base(name) { }
    public override void MakeSound() {
        Console.WriteLine($"{Name} лает: Гав!");
    }
}

Задание 3: Интерфейс

Опишите интерфейс IFeedable с методом Feed(int amount) и реализуйте его в классе Dog, уменьшая внутреннее поле hunger.

public interface IFeedable {
    void Feed(int amount);
}

public class Dog : Animal, IFeedable {
    private int hunger = 100;
    public Dog(string name) : base(name) { }

    public void Feed(int amount) {
        hunger = Math.Max(0, hunger - amount);
    }
}

Задание 4: Абстрактный класс

Сделайте Animal абстрактным классом с абстрактным методом MakeSound() без реализации по умолчанию. Что изменится в классе Dog?

public abstract class Animal {
    public string Name { get; set; }
    public Animal(string name) { Name = name; }
    public abstract void MakeSound(); // без тела!
}

// Dog теперь ОБЯЗАН реализовать MakeSound(), иначе код не скомпилируется.
// var a = new Animal("x"); тоже стало невозможным.
