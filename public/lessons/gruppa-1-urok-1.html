1. Типы данных и переменные

C# — строго типизированный язык. Это значит, что при объявлении переменной мы обязаны указать тип данных, который она будет хранить, и компилятор проверит, что мы не пытаемся положить туда что-то другое.

ТипОписаниеДиапазон / особенностьПример
int Целые числа от −2 147 483 648 до 2 147 483 647 int score = 100;
long «Большие» целые числа используется, когда int переполняется long population = 8000000000L;
double / float Числа с плавающей точкой double точнее, используется по умолчанию double speed = 12.5;
decimal Точные дробные числа для денег и финансовых расчётов decimal price = 19.99m;
string Текст (строки) неизменяемый (immutable) тип string name = "Player";
bool Логический (истина/ложь) только true или false bool isAlive = true;
char Один символ всегда в одинарных кавычках char grade = 'A';

var — вывод типа

Ключевое слово var не делает переменную «динамической» — тип по-прежнему фиксируется, просто компилятор выводит его сам из правой части выражения.

var count = 10;      // компилятор понимает: это int
var title = "Урок";  // компилятор понимает: это string
// count = "текст"; — так сделать нельзя, count навсегда int

const и readonly

Если значение не должно меняться после присвоения, используйте const (значение известно на этапе компиляции) или readonly (можно присвоить один раз, например в конструкторе).

const double Pi = 3.14159;
public readonly string Id;

Приведение типов (casting)

Неявное преобразование происходит автоматически, если данные не теряются (например, int → double). Явное преобразование требует указать тип в скобках и может привести к потере точности.

int a = 10;
double b = a;             // неявно: int -> double, безопасно

double c = 9.7;
int d = (int)c;         // явно: 9.7 -> 9, дробная часть отбрасывается

2. Условия и циклы

Конструкции для управления потоком выполнения программы.

Условный оператор if-else

if (health <= 0) {
    Console.WriteLine("Game Over");
} else if (health < 20) {
    Console.WriteLine("Критично мало здоровья!");
} else {
    Console.WriteLine("Keep playing!");
}

switch — когда вариантов много

switch (level) {
    case 1:
        Console.WriteLine("Новичок");
        break;
    case 2:
        Console.WriteLine("Опытный");
        break;
    default:
        Console.WriteLine("Неизвестный уровень");
        break;
}

Цикл for (когда известно количество шагов)

for (int i = 0; i < 5; i++) {
    Console.WriteLine($"Шаг {i}"); // Выполнится 5 раз: 0,1,2,3,4
}

Цикл while и do-while

while проверяет условие до выполнения тела, а do-while — после, поэтому тело do-while выполнится хотя бы один раз.

int ammo = 3;
while (ammo > 0) {
    Console.WriteLine("Выстрел!");
    ammo--;
}

int attempts = 0;
do {
    attempts++;
} while (attempts < 1); // выполнится минимум 1 раз

Цикл foreach (для перебора коллекций)

string[] weapons = { "Sword", "Bow", "Axe" };
foreach (var w in weapons) {
    Console.WriteLine(w);
}

3. Классы и структуры (основы ООП)

Классы (reference types) и структуры (value types) позволяют создавать собственные типы данных, объединяя состояние (поля/свойства) и поведение (методы).

public class Tank {
    // Поля — храним данные
    private int armor;

    // Свойства — контролируемый доступ к полям
    public string Name { get; set; }
    public int Armor {
        get => armor;
        set => armor = value < 0 ? 0 : value; // не даём уйти в минус
    }

    // Конструктор — вызывается при создании объекта
    public Tank(string name, int armor) {
        Name = name;
        Armor = armor;
    }

    // Метод — поведение объекта
    public void TakeDamage(int damage) {
        Armor -= damage;
        Console.WriteLine($"Танк {Name} получил урон! Броня: {Armor}");
    }
}

// Использование
Tank myTank = new Tank("Т-34", 100);
myTank.TakeDamage(20);

Поля vs свойства

Поле (field) — просто переменная внутри класса. Свойство (property) выглядит как поле снаружи, но на самом деле это пара методов get/set, которая позволяет добавить логику проверки, как в примере выше с броней, которая не может стать отрицательной.

static — принадлежит классу, а не объекту

Обычные поля и методы принадлежат каждому конкретному объекту. Члены с модификатором static — общие для всего класса, их не нужно создавать через new.

public class GameStats {
    public static int TotalTanksCreated = 0;
}

// Обращение напрямую через имя класса, без new
GameStats.TotalTanksCreated++;

4. Методы и параметры

Метод — это именованный блок кода, который можно вызывать многократно. У метода есть тип возвращаемого значения, имя и список параметров.

public int GetMax(int a, int b) {
    return a > b ? a : b;
}

// void означает, что метод ничего не возвращает
public void PrintHello(string name) {
    Console.WriteLine($"Привет, {name}!");
}

Параметры по умолчанию

public void Heal(int amount = 10) {
    Console.WriteLine($"Восстановлено {amount} HP");
}

Heal();      // восстановит 10
Heal(50);    // восстановит 50

Перегрузка методов (overloading)

Можно объявить несколько методов с одним именем, но разным набором параметров — компилятор сам выберет нужную версию по количеству и типам аргументов.

public int Add(int a, int b) => a + b;
public double Add(double a, double b) => a + b;
public int Add(int a, int b, int c) => a + b + c;

foreach (int n in nums) {
    if (n > 0) {
        Console.WriteLine(n);
    }

Задание 3: Класс со свойством

Создайте класс Player со свойствами Name (string) и Health (int, от 0 до 100), а также методом TakeDamage(int damage), который не даёт здоровью уйти ниже нуля.

public class Player {
    private int health;
    public string Name { get; set; }
    public int Health {
        get => health;
        set => health = Math.Clamp(value, 0, 100);
    }

    public void TakeDamage(int damage) {
        Health -= damage;
    }
}

7. LINQ

LINQ (Language-Integrated Query) — это мощный инструмент в C#, который позволяет работать с коллекциями (массивами, списками) короче, читабельнее и без написания громоздких циклов.

Императивный подход (циклы) отвечает на вопрос «КАК сделать?». LINQ — это декларативный подход, он отвечает на вопрос «ЧТО мы хотим получить?».

Сравнение: как мы делали раньше vs как делать с LINQ

Задача: у нас есть список танков. Нужно получить список имён всех танков, у которых броня больше 50.

Старый способ (циклы):

List<string> strongTanks = new List<string>();
foreach (var t in tanks) {
    if (t.Armor > 50) {
        strongTanks.Add(t.Name);
    }
}

Новый способ (LINQ):

// Не забудьте using System.Linq; в начале файла
var strongTanks = tanks
    .Where(t => t.Armor > 50)    // Фильтруем (оставляем тех, кто с бронёй > 50)
    .Select(t => t.Name)       // Выбираем только их имена
    .ToList();                 // Превращаем результат обратно в список

Базовые методы LINQ

МетодЧто делаетАналог без LINQ
Where()Фильтрация элементов по условиюif внутри цикла
Select()Трансформация — выбрать/преобразовать свойствосоздание нового списка в цикле
OrderBy() / OrderByDescending()Сортировка по возрастанию/убываниюручная сортировка
FirstOrDefault()Первый элемент, подходящий под условие, либо null/defaultforeach + break
Any()Есть ли хотя бы один подходящий элемент (bool)флаг + цикл
Count()Количество элементов (по условию или без)счётчик в цикле
Sum() / Average() / Max() / Min()Агрегатные вычислениянакопление в переменной

Метод-цепочки и ленивые вычисления

LINQ-запросы можно соединять в цепочку — каждый метод возвращает новую последовательность, к которой можно применить следующий метод. Важно помнить, что многие LINQ-операции выполняются лениво: реальное вычисление происходит только тогда, когда вы перебираете результат (например, вызовом ToList() или в foreach).

var result = tanks
    .Where(t => t.Armor > 30)
    .OrderByDescending(t => t.Armor)
    .Select(t => $"{t.Name} ({t.Armor})")
    .ToList();
