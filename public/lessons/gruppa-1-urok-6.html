1. Зачем нужна асинхронность

Синхронный код выполняется последовательно: каждая строка ждёт завершения предыдущей. Если одна операция долгая (запрос к серверу, чтение файла), вся программа «замирает».

Проблема: синхронное чтение

Поток UI
Загрузка данных... (3 сек) — интерфейс замёрз

Пока загружаются данные, пользователь не может кликать кнопки, скроллить, вводить текст.

Решение: асинхронные операции

Поток UI
Запрос
Свободен — UI работает
Обработка
Задача
Загрузка в фоне

Типичные асинхронные операции

ОперацияСинхронноАсинхронно
HTTP-запросHttpClient.Send()await HttpClient.SendAsync()
Чтение файлаFile.ReadAllText()await File.ReadAllTextAsync()
Запрос к БДToList()await ToListAsync()
ПаузаThread.Sleep()await Task.Delay()

2. Task и Task<T>

Task — это обещание (promise)未来的 результата. Метод возвращает Task, когда работа ещё не завершена, но будет когда-нибудь.

Task (без возврата)

// Task — для void-методов
static Task SaveDataAsync() {
    return Task.Delay(2000); // имитация 2 секунд работы
}

// Использование
Task task = SaveDataAsync();
await task; // ждём завершения

Task<T> (с возвратом значения)

// Task<T> — возвращает значение типа T
static Task<int> GetCountAsync() {
    return Task.FromResult(42); // мгновенное завершение
}

// Использование
int count = await GetCountAsync(); // count = 42

Свойства Task

СвойствоОписание
IsCompletedЗадача завершилась? (bool)
IsFaultedЗавершилась с ошибкой? (bool)
IsCanceledБыла отменена? (bool)
ResultРезультат (блокирует поток — не используйте без await!)
ExceptionИнформация об ошибке

Создание Task

// Завершённая задача
Task<int> finished = Task.FromResult(10);

// Задача с ошибкой
Task failed = Task.FromException(new InvalidOperationException("Ошибка!"));

// Задача с задержкой
Task delayed = Task.Delay(1000);

3. async и await

async и await — синтаксический сахар для работы с Task. Под капотом — state machine, который приостанавливает метод и возобновляет при завершении задачи.

Правила

ПравилоПример
async ставится перед методомasync Task<int> GetDataAsync()
await ставится перед Taskint r = await GetDataAsync();
await можно только в async-методеКомпилятор запретит await без async
Метод с async возвращает Task / Task<T>Или void (но void — плохо!)
static async Task<string> LoadDataAsync() {
    Console.WriteLine("Начинаю загрузку...");

    await Task.Delay(2000); // приостанавливаем метод на 2 сек

    Console.WriteLine("Загрузка завершена!");
    return "Данные из API";
}

// Вызов
string data = await LoadDataAsync();
Console.WriteLine(data); // Данные из API

Что делает await

  1. Вызывает Task-метод
  2. Приостанавливает текущий метод (не блокирует поток!)
  3. Поток возвращается в пул (свободен для других задач)
  4. Когда Task завершается — метод возобновляется

Паттерн: несколько await

static async Task ProcessOrderAsync() {
    Console.WriteLine("1. Принимаем заказ...");
    await Task.Delay(1000);

    Console.WriteLine("2. Оплата...");
    await Task.Delay(1500);

    Console.WriteLine("3. Отправка...");
    await Task.Delay(2000);

    Console.WriteLine("4. Готово!");
}

4. Когда await НЕ работает

Есть ситуации, когда await ведёт себя неожиданно или его нельзя использовать.

1. void-методы

// ПЛОХО: async void — нельзя await, сложно ловить ошибки
static async void BadMethod() {
    await Task.Delay(1000);
}

// ХОРОШО: async Task — можно await и ловить исключения
static async Task GoodMethod() {
    await Task.Delay(1000);
}

2. Ловушки синхронного кода

// ПЛОХО: блокирующий вызов — может вызвать deadlock!
string result = LoadDataAsync().Result;     // блокирует поток
LoadDataAsync().Wait();                     // тоже блокирует

// ХОРОШО: всегда используйте await
string result = await LoadDataAsync();

3. Конструкторы и свойства

// Нельзя сделать конструктор async
public MyClass() {
    await ...; // ОШИБКА КОМПИЛЯЦИИ
}

// Решение — статический фабричный метод
public static async Task<MyClass> CreateAsync() {
    var obj = new MyClass();
    await obj.InitAsync();
    return obj;
}

4. foreach и await

// Последовательно — каждый await ждёт предыдущего
foreach (var url in urls) {
    await DownloadAsync(url); // 1, потом 2, потом 3...
}

// Параллельно — см. раздел 5 (Task.WhenAll)

5. Task.WhenAll и Task.WhenAny

Два ключевых метода для параллельной работы с несколькими задачами.

Task.WhenAll — ждём все задачи

// Запускаем 3 загрузки параллельно
Task<string> task1 = DownloadAsync("api/users");
Task<string> task2 = DownloadAsync("api/posts");
Task<string> task3 = DownloadAsync("api/comments");

// Ждём ВСЕ три одновременно
string[] results = await Task.WhenAll(task1, task2, task3);

// results[0], results[1], results[2] — результаты каждой задачи

Task.WhenAny — ждём первую задачу

// Какой сервер ответит быстрее?
Task<string> server1 = FetchFromAsync("server1");
Task<string> server2 = FetchFromAsync("server2");

Task<string> winner = await Task.WhenAny(server1, server2);
string fastResult = await winner; // результат от быстрого сервера

Сравнение

МетодЖдётКогда использовать
awaitОдну задачуКогда важен результат конкретной задачи
Task.WhenAll()Все задачиКогда нужны все результаты
Task.WhenAny()Первую задачуТаймаут, гонка серверов, fallback

6. CancellationToken

CancellationToken — механизм отмены长时间运行的 задач. Пользователь нажал «Отмена»? Закрытие приложения? Таймаут? — сигнал об отмене передаётся через токен.

static async Task DownloadAsync(CancellationToken ct) {
    for (int i = 0; i < 100; i++) {
        ct.ThrowIfCancellationRequested(); // бросит OperationCanceledException

        Console.WriteLine($"Загрузка... {i}%");
        await Task.Delay(100, ct);
    }
}

// Использование
var cts = new CancellationTokenSource();
var token = cts.Token;

// Запускаем задачу
Task task = DownloadAsync(token);

// Через 3 секунды отменяем
await Task.Delay(3000);
cts.Cancel(); // сигнал отмены

try {
    await task;
}
catch (OperationCanceledException) {
    Console.WriteLine("Загрузка отменена!");
}

Таймаут через CancellationToken

// Автоматическая отмена через 5 секунд
var cts = new CancellationTokenSource();
cts.CancelAfter(5000);

await LongRunningAsync(cts.Token);

static async Task<string> LoadDataAsync() {

Задание 2: Параллельные запросы

Запустите 3 задачи параллельно с помощью Task.WhenAll и выведите результаты.

static async Task<string> FetchAsync(string url) {
    await Task.Delay(1000); // имитация запроса

}

var t1 = FetchAsync("api/users");
var t2 = FetchAsync("api/posts");
var t3 = FetchAsync("api/comments");

string[] results = await Task.WhenAll(t1, t2, t3);

    Console.WriteLine(r);

Задание 3: Таймаут

Напишите метод, который «загружает» данные, но отменяется через 3 секунды, если не завершился.

static async Task FetchWithTimeoutAsync() {
    var cts = new CancellationTokenSource();
    cts.CancelAfter(3000);

    try {
        await LongRunningAsync(cts.Token);
    }
    catch (OperationCanceledException) {
        Console.WriteLine("Таймаут: операция отменена");
    }
}

static async Task LongRunningAsync(CancellationToken ct) {
    for (int i = 0; i < 10; i++) {
        ct.ThrowIfCancellationRequested();
        Console.WriteLine($"Работаю... {i}");
        await Task.Delay(1000, ct);
    }
}

Задание 4: Фабричный метод

Создайте класс Database с асинхронной инициализацией через статический метод CreateAsync().

public class Database {
    public string ConnectionString { get; private set; }

    private Database() { }

    public static async Task<Database> CreateAsync(string connStr) {
        var db = new Database();
        await db.ConnectAsync(connStr);
        return db;
    }

    private async Task ConnectAsync(string connStr) {
        await Task.Delay(1000); // имитация подключения
        ConnectionString = connStr;
    }
}

// Использование
var db = await Database.CreateAsync("Server=mydb");
