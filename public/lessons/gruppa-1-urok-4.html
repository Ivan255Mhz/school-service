1. Что такое исключение

Исключение (exception) — это объект, который среда выполнения создаёт и «выбрасывает», когда во время работы программы происходит нештатная ситуация: деление на ноль, обращение к несуществующему индексу массива, попытка использовать null как объект и так далее.

Если исключение никто не «поймал», программа аварийно завершается, а пользователь видит малопонятную ошибку. Обработка исключений позволяет предугадать проблемные места и красиво отреагировать на них — вывести понятное сообщение, повторить попытку или просто не уронить всё приложение из-за одной операции.

int[] scores = { 10, 20, 30 };
Console.WriteLine(scores[10]); // программа упадёт: IndexOutOfRangeException

2. try / catch / finally

Код, который потенциально может выбросить исключение, оборачивается в блок try. Если исключение произошло, выполнение try немедленно прерывается и управление передаётся в подходящий блок catch. Блок finally выполняется всегда — было исключение или нет.

try {
    int a = 10;
    int b = 0;
    int result = a / b;               // здесь произойдёт исключение
    Console.WriteLine("Это не выполнится");
} catch (DivideByZeroException ex) {
    Console.WriteLine($"Ошибка: {ex.Message}");
} finally {
    Console.WriteLine("Этот блок выполнится в любом случае");
}

finally обычно используют для «уборки» — закрытия файлов, соединений с базой данных или освобождения других ресурсов, независимо от того, как завершился try.

4. Иерархия встроенных исключений

Все исключения в .NET наследуются от базового класса System.Exception. Это тоже пример полиморфизма из прошлого урока: можно поймать catch (Exception ex) и обработать любую ошибку, а можно ловить конкретные типы для более точной реакции.

Класс исключенияКогда возникает
DivideByZeroExceptionДеление целого числа на ноль
IndexOutOfRangeExceptionОбращение к индексу массива за его границами
NullReferenceExceptionОбращение к члену объекта, который равен null
FormatExceptionНапример, int.Parse("abc") — строку нельзя превратить в число
ArgumentException / ArgumentNullExceptionМетоду передан некорректный или null аргумент
KeyNotFoundExceptionОбращение к несуществующему ключу в Dictionary
InvalidOperationExceptionОперация недопустима в текущем состоянии объекта

У каждого исключения есть полезные свойства: Message (текст ошибки), StackTrace (путь вызовов, где произошла ошибка) и InnerException (вложенное исключение, если ошибка была «завёрнута» в другую).

6. Несколько catch-блоков и порядок важен

Можно указать несколько catch для разных типов исключений — они проверяются сверху вниз, и сработает первый подходящий. Поэтому более «узкие» (специфичные) исключения нужно ставить выше общего catch (Exception ex), иначе он перехватит всё раньше, а специфичные блоки станут недостижимым кодом.

try {
    int[] data = new int[3];
    int value = data[5] / 0;
} catch (DivideByZeroException ex) {
    Console.WriteLine("Деление на ноль!");       // более специфично
} catch (IndexOutOfRangeException ex) {
    Console.WriteLine("Индекс вне диапазона!"); // более специфично
} catch (Exception ex) {
    Console.WriteLine("Какая-то другая ошибка");  // самый общий — в конце
}

Правильный порядок этой задачи: сначала обратится к data[5], что вне диапазона массива из 3 элементов — сработает именно IndexOutOfRangeException, а деление на ноль просто не будет достигнуто.

7. Свои классы исключений

Когда встроенных исключений недостаточно, чтобы описать ошибку бизнес-логики (например, «недостаточно золота» или «неверный уровень персонажа»), можно создать собственный класс исключения, унаследовав его от Exception.

public class NotEnoughGoldException : Exception {
    public int Required { get; }
    public int Available { get; }

    public NotEnoughGoldException(int required, int available)
        : base($"Нужно {required} золота, доступно только {available}.") {
        Required = required;
        Available = available;
    }
}

// Использование:
public void BuyItem(int price, int playerGold) {
    if (price > playerGold) {
        throw new NotEnoughGoldException(price, playerGold);
    }
    Console.WriteLine("Покупка успешна!");
}

try {
    BuyItem(100, 30);
} catch (NotEnoughGoldException ex) {
    Console.WriteLine(ex.Message); // "Нужно 100 золота, доступно только 30."
}

Своё исключение делает код читабельнее и позволяет обрабатывать конкретно эту ситуацию, не путая её с другими ошибками программы.

9. throw; vs throw ex; — тонкость, которая ломает отладку

Если вы ловите исключение и хотите передать его дальше (например, залогировав), важно использовать именно throw; без указания переменной, а не throw ex;.

try {
    DoRiskyOperation();
} catch (Exception ex) {
    LogError(ex);
    throw;      // ✅ сохраняет исходный StackTrace — видно, где ошибка произошла на самом деле
    throw ex;   // ❌ "перезаписывает" StackTrace текущим местом, теряя историю вызовов
}

Это частая ошибка даже у опытных разработчиков: throw ex; компилируется без предупреждений, но при отладке в проде вы увидите, что исключение «началось» в блоке catch, а не там, где оно реально произошло — что сильно усложняет поиск причины.

10. Практические задания

Задание 1: Простой try/catch

Напишите метод SafeDivide(int a, int b), который делит два числа и возвращает 0, если b равен нулю, перехватывая DivideByZeroException.

public int SafeDivide(int a, int b) {
    try {
        return a / b;
    } catch (DivideByZeroException) {
        return 0;
    }
}

Задание 2: finally для «уборки»

Напишите блок кода, который пытается распарсить строку в число (int.Parse), а в finally всегда выводит «Попытка парсинга завершена», независимо от результата.

try {
    int value = int.Parse("abc");
    Console.WriteLine(value);
} catch (FormatException ex) {
    Console.WriteLine($"Не удалось распознать число: {ex.Message}");
} finally {
    Console.WriteLine("Попытка парсинга завершена");
}

Задание 3: своё исключение

Создайте класс InvalidAgeException : Exception и метод SetAge(int age), который выбрасывает это исключение, если age отрицательный или больше 150.

public class InvalidAgeException : Exception {
    public InvalidAgeException(string message) : base(message) { }
}

public void SetAge(int age) {
    if (age < 0 || age > 150) {
        throw new InvalidAgeException($"Некорректный возраст: {age}");
    }
    // сохранить age...
}

Задание 4: несколько catch

Напишите метод, который принимает строку и делитель, парсит строку в число и делит его на делитель, корректно обрабатывая и FormatException, и DivideByZeroException отдельными блоками catch.

public void ParseAndDivide(string input, int divisor) {
    try {
        int number = int.Parse(input);
        Console.WriteLine(number / divisor);
    } catch (FormatException) {
        Console.WriteLine("Некорректный формат числа");
    } catch (DivideByZeroException) {
        Console.WriteLine("Нельзя делить на ноль");
    }
}
